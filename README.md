# 서가은 포트폴리오

기획한 의도가 화면과 실제 동작으로 이어지도록, 문제를 발견하고 수정 기준을 구체화합니다.

웹 서비스와 게임 프로젝트에서 화면 흐름, API 연동 점검, 아트 제작 과정, 플레이 검수와 발표 구성에 참여했습니다. AI와 협업할 때에도 결과물을 직접 확인하고, 원하는 동작과 다른 지점을 구체적으로 설명하는 데 집중했습니다.

## 대표 프로젝트

| 프로젝트 | 서비스 | 주로 다룬 일 | 사례 |
|---|---|---|---|
| **[AIVO](projects/aivo.md)** | 발표·면접 연습 피드백 서비스 | 프론트엔드 화면 흐름, 면접·폴더 API 연동 점검, 리포트 검수 | 화면 표시와 실제 API 연결 구분 / 리포트 집계 기준 점검 |
| **[한짝](projects/hanjjak.md)** | 웹 방치형 게임 | 치장 아트 제작 흐름, 프레임·레이어 검수, 게임 화면 반영 점검 | 고정 마네킹을 기준으로 장비 제작 / 모션 사이의 그림 일관성 유지 |
| **[DEVIANT](projects/deviant.md)** | Unity 2D 액션 로그라이트 | 조작 흐름, 전투 체감 검수, HUD·리소스 표현 기준 | 제작·장착 흐름 재설계 / 프로토타입과 Unity 동작 차이 추적 |

프로젝트별 페이지는 **문제 → 내 판단 → 진행 과정 → 결과와 배운 점** 순서로 구성했습니다. 팀 전체 기능과 개인이 맡은 일을 구분해 적었습니다.

## 작업 방식

- 실제 화면이나 플레이에서 불편한 지점을 먼저 확인합니다.
- 수정 전에 비교할 수 있는 시안과 프로토타입으로 요구를 구체화합니다.
- AI의 완료 설명에만 의존하지 않고 실제 응답·표시·조작 결과를 확인합니다.
- 팀원의 구현, AI가 수행한 작업, 제가 내린 판단과 검수를 구분합니다.
