# AIVO

발표와 면접 연습을 녹화하고, 음성·영상·내용에 대한 피드백을 확인하며 다시 연습하는 AI 코칭 서비스입니다.

## 맡은 일

팀의 프론트엔드 작업에 참여했습니다. 화면과 사용자 흐름을 구체화하고, 면접·폴더 API 연결과 리포트 표시를 점검했습니다. Vue 화면 구조와 UI를 다듬는 과정에서 AI 구현 결과를 실제 화면·자료·서버 응답과 대조했습니다.

| 구분 | 범위 |
|---|---|
| 직접 한 판단과 검수 | 화면 요구와 수정 기준 제시, Mock과 실제 연동 구분 요청, 리포트 수치 불일치 발견, 실제 화면 확인 |
| AI와 협업한 작업 | Vue 코드 수정, API 호출 경로 점검과 수정, 테스트·빌드 실행 결과 확인 |
| 팀과 구분한 범위 | 백엔드와 AI 분석 기능 전체를 제 개인 구현 성과로 포함하지 않습니다. |

## 사례 1 화면 표시와 실제 API 연결 구분

### 문제

API 요청 실패를 Mock 응답으로 대체하는 경로 때문에, 화면이 정상적으로 보이는 것과 실제 서버 연동이 완료된 것을 혼동할 수 있었습니다. 로컬 백엔드 소스와 배포 서버의 상태 차이도 확인 과정에 영향을 줬습니다.

### 판단과 진행

면접·폴더 기능을 확인할 때 가짜 응답으로 성공처럼 보이지 않도록 요청했습니다. 기능을 실제로 실행한 뒤 요청 Method, URL, 상태 코드와 JSON 응답을 명세와 함께 확인하는 방식으로 상태를 나눴습니다.

| 확인 단계 | 살펴본 기준 |
|---|---|
| 화면 구현 | 화면과 입력 흐름이 있는가 |
| 프론트 호출 | 해당 기능을 실행했을 때 요청이 발생하는가 |
| 서버 응답 | 요청에 맞는 상태 코드와 데이터가 오는가 |
| 기능 완료 | 응답 이후 화면과 저장 결과까지 맞는가 |

### 결과와 배운 점

당시 기록에서 폴더 조회·생성의 정상 응답을 확인했고, 면접 리포트 재조회 실패는 별도 확인 항목으로 남겼습니다. 일부 API 응답을 확인한 결과를 전체 연동 완료로 확대하지 않고, 확인한 범위를 구분해 기록했습니다.

## 사례 2 리포트의 총합과 질문별 근거 맞추기

### 문제

면접 리포트에서 시선 이탈의 전체 수치와 질문별 합계가 맞지 않았습니다. 그래프가 있다는 것만으로 사용자가 결과를 이해할 수 있는 상태는 아니었습니다.

### 판단과 진행

전체 요약과 질문별 근거를 같은 기준으로 표시하도록 요청했습니다. 데이터가 없는 경우와 데이터가 있지만 프론트에서 숨겨진 경우를 구분해 확인했습니다.

### 결과와 배운 점

리포트의 표시 기준을 맞추는 수정에 참여했습니다. 이 사례는 분석 모델의 정확도 개선이 아니라, 서버 응답과 화면에서 설명하는 수치의 일관성을 점검한 경험입니다.
