# DEVIANT

잉크와 스케치 분위기의 Unity 2D 액션 로그라이트입니다. 플레이어가 느끼는 전투 체감과 조작 흐름, 화면 표현을 구체화하고 검수하는 작업에 참여했습니다.

## 맡은 일

직접 플레이하며 불편한 부분을 짚고, HTML 프로토타입과 비교 시안으로 원하는 동작을 설명했습니다. AI와 협업한 구현을 Unity에서 다시 확인하며 화면 흐름과 전투 타이밍의 차이를 조정했습니다.

| 구분 | 범위 |
|---|---|
| 직접 한 판단과 검수 | 전투 체감 우선순위, UI 조작 순서, 비교 시안 선택, HUD 표현 기준, 플레이 피드백 |
| AI와 협업한 작업 | HTML 비교 도구, Unity 코드 수정, 리소스 보정과 검사·테스트 실행 |
| 팀과 구분한 범위 | 잉크·파츠 시스템의 원안과 팀원 이펙트 등은 팀 기여로 구분합니다. |

## 사례 1 제작과 장착 흐름 다시 설계하기

### 문제

여러 슬롯을 제작하고 장착하는 동안 같은 확인 단계를 반복해야 했습니다. 한 키가 여러 행동을 맡아 현재 무엇이 실행되는지도 쉽게 파악하기 어려웠습니다.

### 판단과 진행

Unity 수정에 앞서 직접 조작할 수 있는 HTML 비교본으로 화면 순서를 확인했습니다. 제작 탭을 따로 오가는 흐름을 줄이고, 제작 완료 화면을 통합하도록 요구했습니다. 바로 교체하고 싶지 않을 때의 보관 선택지도 포함했습니다.

선택 전후의 강조, 사용할 수 없는 영역의 표시, 완료 후 복귀 흐름을 나눠 검수했습니다. 팀원이 변경 내용을 이해할 수 있도록 설명도 글 중심에서 화면 중심으로 정리했습니다.

### 결과와 배운 점

제작·장착 흐름 수정이 메인 코드에 반영됐습니다. 프로토타입에서 조작 순서를 검토한 뒤 실제 게임에 적용하는 과정을 경험했습니다. 팀원이 설계한 잉크 규칙과 제가 개선한 화면·조작 흐름은 구분했습니다.

## 사례 2 프로토타입과 Unity의 전투 체감 차이 추적하기

### 문제

HTML 시험장에서 맞춘 전투 설정을 Unity에 옮겼는데도 같은 손맛이 나지 않았고, 플레이 중 느려지는 현상이 있었습니다.

### 판단과 진행

액션의 시원함을 우선 기준으로 두고 직접 플레이한 차이를 전달했습니다. 단순히 효과 수치를 더 키우기보다, 현재 Unity 상태를 HTML에 재현해 비교하도록 요청했습니다. 비교 과정에서 공격 클립의 재생 시간표가 체감에 영향을 주는 문제를 추적했습니다.

카메라 확대 방식과 공격 타이밍을 다시 확인하고, 플레이 검수를 거쳐 반영 방향을 정했습니다.

### 결과와 배운 점

전투 타이밍과 피격 반응을 조정하는 수정이 메인 코드에 반영됐습니다. 설정값이 같아도 엔진에서 재생되는 방식이 다르면 체감이 달라진다는 점을 배웠습니다. 구현 코드는 AI와 협업했으며, 저는 비교 기준과 수정 방향, 플레이 확인을 맡았습니다.

## 화면 표현 작업

전투 HUD의 픽셀 표현 통일, 무기·스킬 아이콘의 식별성, 게이지와 캐릭터 효과의 역할 구분도 다뤘습니다. 장식의 양보다 플레이 중 정보를 읽을 수 있는지를 기준으로 시안을 선택하고 수정했습니다.
